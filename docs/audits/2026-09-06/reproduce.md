# Reproducing the release audit

The production and source-harness checks intentionally have separate URLs. All browser scripts create disposable contexts: they do not attach to the user's browser profile or saved rooms. The scripts are diagnostic evidence, not an integrated CI suite or an application fix.

1. Install the repository's locked dependencies and run `npm run check`. For coverage, the audit used `npm test -- --coverage --coverage.reporter=json-summary --coverage.reporter=text --coverage.reportsDirectory=/tmp/roomplanner-release-evidence/coverage`.
2. Run `npm run build:production`, then `npx wrangler dev --config dist/server/wrangler.json --port 8788`. The app is at `http://localhost:8788/RoomPlaner`.
3. Install Playwright and `@axe-core/playwright` into a separate temporary tools directory. The audit used Playwright 1.63.0 and axe integration 4.13.0. Copy the scripts from this folder into that tools directory so Node can resolve those dependencies. Install the desired browser engines. Chromium evidence here used Helium 152; WebKit evidence used the already installed build 2336 reporting WebKit 26.6. Default browser paths in the retained scripts describe this machine. Update them for another host, or set `AUDIT_BROWSER` for Chromium. The WebKit script retains its explicit engine path to distinguish it from the failed build-2359 download.
4. Create `/tmp/roomplanner-release-evidence`, or set `AUDIT_OUTPUT` to an existing directory. Run `release-ui.mjs` for Chromium and `release-webkit.mjs` for the recorded WebKit path. They test initial/selected states, JSON/PNG downloads, room resizing, and reload persistence at five viewports. `AUDIT_PRODUCTION_URL` can override the production URL.
5. Run `layout-edges.mjs` to reproduce clipped Settings, and `production-metrics.mjs` for one local, unthrottled production load. The short-height case approximates constrained space only; it does not emulate a real mobile keyboard.
6. For source probes, run `harness-server.mjs` from the repository checkout. It launches Vite at port 3011 with React and Tailwind, mounting the actual `PlannerWorkspace`. This script retains absolute repository/module paths from the audited machine; update them if relocating the checkout. It makes no source edits. It bypasses Vinext and Worker SSR intentionally, because the ordinary dev command failed hydration during this audit. Do not report source-harness success as a pass for `npm run dev`.
7. With that harness running, run `adversarial.mjs`, `persistence-touch.mjs`, `gestures.mjs`, `import-edges.mjs`, and `final-probes.mjs`. `AUDIT_SOURCE_URL` can override the source URL. The import probes create bounded synthetic files and measure validation without mounting the huge plan. The storage-denial context uses a throwing localStorage getter as fault injection. `persistence-touch.json` supplies the actual two-tab save-conflict reproduction; the preliminary synthetic save-error timing in `adversarial.json` is not used as proof of the timeout defect. The exploratory pan in `persistence-touch.json` was affected by the closing sheet transition; use `gestures.json` for the independently verified current pan/drag/pinch behavior.
8. Copy the earlier `docs/audits/2026-09-05/scripts/verify-audit.mjs` to the tools directory and run it with `AUDIT_URL=http://localhost:3011`, `AUDIT_BROWSER`, and a separate existing `AUDIT_OUTPUT` directory for the fresh catalog matrix. This is a source SVG-envelope/accessibility/selection-timing suite. It does not certify manufacturer dimensions.
9. Run the retained `verify-persistence.mjs` with the same source-harness variables for adapted regression checks. It is the previous `verify-fixes.mjs` with only its obsolete Pan-button section replaced by an explicit skip. Assertions for conflict/copy recovery, atomic deletion, delayed saves, colors, locking, TV families, exports and toolbar bounds remain. Use the new gesture checks for touch behavior. The old `verify-mobile.mjs` still describes a previous interaction model and was not claimed as passing.
10. Stop the production Worker before rebuilding the same `dist` directory for development. Run `npm run build:develop`, create ignored `dist/server/.dev.vars` with a newly generated local-only `DEV_PASSWORD`, and launch Wrangler on port 8789 with a fresh local persistence directory. Run `scripts/test-deployment.mjs` with `TEST_ORIGIN=http://localhost:8789` and the local `TEST_PASSWORD` supplied through the environment, without logging it. The smoke test intentionally consumes the local attempt budget. `deploy-extra.mjs` checks content type, oversized body, and null Origin before password verification. Do not run password/rate-limit probes against a live deployment.

The audit did not use stored account secrets. It generated a local test password, which was removed when the output directory was rebuilt for production. The final generated output is the production build. No source files were changed to make a test pass.

The normal development-command failure was observed both before and after restarting it: root HTML returned 200 but `/app/globals.css` and `/@id/__x00__virtual:vite-rsc/entry-browser` returned 404, so the editor never hydrated. Investigate the framework/plugin integration separately from the temporary harness.

Fresh evidence is linked in [the audit](audit.md). Failed browser download logs document why Firefox and the newer WebKit binary were not used. Browser, OS, hardware, CPU, caches, and network conditions affect performance results; this audit's timing values are not release thresholds.
